Section 1 — Design Flaws

Visual, layout, CSS, typography, and branding inconsistencies

10 bugs found
BUG-DESIGN-001 Wrong Image in "How It Works" Section (VR Headset) 🔴 Critical
PageHomepage /
SectionHow It Works
TypeWrong Content

The "How It Works" section (01 Choose a Service → 02 Book a Schedule → 03 Get it Done) displays a VR/AR headset (Oculus Meta Quest) as its main illustration. This is completely unrelated to home services (AC repair, plumbing, cleaning). It severely damages brand credibility and confuses first-time visitors.

Steps to Reproduce
  • 1Open https://fixzone.com.bd/
  • 2Scroll down past the hero section
  • 3Find the "How It Works" section — observe the image on the left
✅ Expected
A relevant image such as a technician fixing an AC, a plumber, or a service booking illustration
❌ Actual
A VR/AR headset (Oculus Meta Quest) with a play-button overlay
BUG-DESIGN-002 Hero Headline Uses Off-Brand Yellow Color 🟠 High
PageHomepage /
SectionHero Banner Headline
TypeBrand Inconsistency

The main hero headline "Smarter services for a simpler life" is rendered in a bright canary yellow that is not part of the Fixzone brand palette (orange #F27C27 + navy #1F417F). This creates brand inconsistency and a jarring contrast against the dark hero background.

✅ Expected
White, brand orange, or navy color matching the design system
❌ Actual
Bright yellow not in the Fixzone brand color system

Page/services/[slug]

❌ Actual
Text clipped: "AC Master Service - I..." with no accessible alternative

Orange #F27C27 consistent with all other CTA elements

Teal/cyan color that is the "accent" color, not the CTA primary

✅ Expected
Display "Faridpur Sadar" or "Faridpur, Bangladesh" as the clean location string
❌ Actual
Raw geocoder result "1no Sarak" shown verbatim on 3 separate pages

Section 2 — Loading Flaws

Slow rendering, client-side bailouts, stuck spinners, and data-fetch failures

6 bugs found
BUG-LOAD-001 Splash Screen Can Permanently Block Content if JavaScript Fails 🔴 Critical
PageAll Pages (Global)
SectionSplash overlay

A full-screen gradient splash screen ("Loading latest services and offers…") blocks all page content until JavaScript resolves. If JS fails to load (CDN down, network drop, or JS error), the splash screen never dismisses, permanently blocking the entire website — users see only a gradient background with the logo.

Steps to Reproduce
  • 1Open DevTools → Network → set throttling to "Slow 3G"
  • 2Reload https://fixzone.com.bd/
  • 3Observe splash screen persisting indefinitely
✅ Expected
Hard timeout (max 3–5s) that always dismisses the splash regardless of JS state
❌ Actual
Splash is entirely JS-dependent with no fallback or maximum display time
BUG-LOAD-002 Services Page Fully Client-Side Rendered — Invisible to Search Engines 🔴 Critical
Page/services
SectionEntire page content
TypeSEO / Performance

The services page source contains BAILOUT_TO_CLIENT_SIDE_RENDERING (Next.js signal that SSR was skipped). The entire catalog depends on client-side JS. Google, Bing, and other crawlers cannot index service listings. On slow connections, users see only a white page with a single spinner.

✅ Expected
Service cards server-side rendered or statically generated (SSG) in initial HTML
❌ Actual
Empty HTML shell + 3× BAILOUT_TO_CLIENT_SIDE_RENDERING — zero SEO content
BUG-LOAD-003 Homepage Also Bails Out to Client-Side Rendering (3 Instances) 🟠 High
Page/ (Homepage)

The homepage source also contains 3 instances of BAILOUT_TO_CLIENT_SIDE_RENDERING covering the navbar, main content, and footer. This causes poor Core Web Vitals (high LCP), delays for first-time visitors, and reduces Google's ability to index homepage content effectively.

✅ Expected
Hero section, featured services, and CTAs are server-rendered in initial HTML
❌ Actual
3× client-side bailouts — high LCP, poor SEO, delayed first paint
BUG-LOAD-004 About Page Stats API Fails Silently — Counters Stuck at 0 🟠 High
Page/about
SectionStatistics counter cards

The About page statistics (Categories, Services, Areas, Active deals) all show 0 even after the page finishes loading. The client-side API call to fetch live platform stats either fails, returns an error silently, or is never made. There is no error message or retry mechanism.

✅ Expected
Dynamic API call returns: Categories: 6, Services: 9, Areas: 28, Deals: [N]
❌ Actual
All 4 counters permanently display 0 with no error state or loading indicator
BUG-LOAD-005 Package Card Thumbnail Images Appear Blurry / Low-Resolution 🟡 Medium
Page/services/[slug]
SectionPackage selection cards

Thumbnail images inside the package selection cards appear at very low resolution and pixelated quality at their rendered size. No srcSet or responsive image optimization is applied, causing blurry output especially on HiDPI/Retina displays.

✅ Expected
Sharp images at all densities using srcSet with 1x and 2x resolution variants
❌ Actual
Single low-res image source served to all devices — blurry on HD screens
BUG-LOAD-006 No Skeleton / Shimmer Loading State for Service Card Grid 🟡 Medium
Page/services
SectionService card grid

When the services catalog is loading data, there is no skeleton card UI. Instead users see a single small spinner centered on a plain grey background, which makes the page feel completely empty and broken, especially on slower connections.

✅ Expected
Shimmer skeleton cards fill the grid area while data loads (industry standard)
❌ Actual
Lone spinner on an empty grey page — poor perceived performance

Section 3 — Functional / Other Bugs

Logic errors, broken features, missing validations, and UX problems

10 bugs found
BUG-FUNC-001 "BOOK SERVICE" Nav CTA Routes to /register Instead of /services 🔴 Critical
PageAll Pages
SectionNavigation Header

The "BOOK SERVICE" button in the navigation header is labelled as a booking action but clicking it takes the user directly to /register (the sign-up page) instead of the services catalog. Unauthenticated users who want to browse services before registering are forced into a registration flow prematurely, violating the standard service discovery → booking funnel.

✅ Expected
Routes to /services so users can browse before being asked to register
❌ Actual
Routes directly to /register — bypasses service discovery entirely
BUG-FUNC-002 Contact Page Shows "28 LIVE AREAS" with No Coverage List Available 🟡 Medium
Page/contact
SectionLeft info panel

The contact page prominently displays "28 LIVE AREAS" as a statistic, but there is no coverage map, list, or link anywhere on the website showing which 28 areas Fixzone serves. Users from outside Faridpur cannot determine if they are within the service zone.

✅ Expected
A coverage map or "View areas" link listing all 28 zones served by Fixzone
❌ Actual
The number is displayed with no linked details or area discovery mechanism
BUG-FUNC-003 Checkout Accessible with Empty Cart via Direct URL 🔴 Critical
Page/checkout
SectionCart guard

Authenticated users can navigate directly to /checkout with zero items in their cart via a direct URL. This could result in ৳0 orders being created in the database if form submission is not also blocked server-side, causing database integrity issues.

✅ Expected
Redirect to /services immediately OR show a clear empty-cart state with a locked Place Order button
❌ Actual
Checkout page accessible with potentially submittable ৳0 order form
BUG-FUNC-004 No OTP or Email Verification on New Account Registration 🔴 Critical
Page/register
TypeSecurity

The registration form creates an account instantly using only Name, Phone, Email, and Password — with no OTP or email verification step. This means anyone can create accounts using fake phone numbers or email addresses they don't own, enabling spam accounts, fake reviews, and potential fraud.

✅ Expected
OTP sent to phone number (or verification email link) required before account activation
❌ Actual
Account created immediately with no identity ownership verification
BUG-FUNC-005 Hero Search Bar Enter Key May Not Submit (Keyboard Accessibility) 🟡 Medium
Page/ (Homepage)
SectionHero search bar

The hero search bar's keyboard behavior (pressing Enter to submit) is not verified. If the input is not inside a proper <form> element, Enter key presses will not trigger navigation to /services?q=[query], breaking keyboard-only users and assistive technology flows.

✅ Expected
Pressing Enter inside the search bar navigates to /services?q=[query] identically to clicking Search
❌ Actual
Enter key behavior unverified — may silently do nothing for keyboard users
BUG-FUNC-006 Location Refresh Icon Provides No Visual Feedback 🟠 High
Page/ (Homepage)
SectionLocation bar

Clicking the directional/refresh arrow next to "Location: Faridpur →" triggers a geolocation update, but provides no loading spinner, animation, or confirmation. On mobile, geolocation can take 3–10 seconds. Users have no indication whether the action is processing or has completed.

✅ Expected
Brief "Locating…" spinner during geolocation; success message updates the label
❌ Actual
No feedback at all — the click feels broken
BUG-FUNC-007 Services Page Title Tag Too Generic — Missing Location Keywords (SEO) 🟠 High
Page/services
SectionHTML <title> tag
TypeSEO

The Services page title is "Home Services & Repairs | Fixzone" — generic, with no mention of Faridpur or Bangladesh. Since Fixzone's market is location-specific, omitting location keywords from the most important SEO signal (the title tag) significantly reduces local search ranking potential.

✅ Expected
AC Repair, Plumbing & Home Services in Faridpur | Fixzone
❌ Actual
Home Services & Repairs | Fixzone — no city/location keyword
BUG-FUNC-008 Register Page Has No "Already Have an Account? Sign In" Link 🟠 High
Page/register
TypeUX / Navigation

The register page has no link back to the login page. Users who land on /register when they meant to log in must use the browser back button or manually type /login. This breaks the standard authentication UX convention and adds friction.

✅ Expected
"Already have an account? Sign In →" link visible below or inside the registration form
❌ Actual
No such link exists — users trapped on the register page
BUG-FUNC-009 Login Input Placeholder Has Typo: "hame@email.com" 🟢 Low
Page/login
SectionEmail/Phone input field

The email/phone input field on the login page displays the placeholder text "hame@email.com or 01XXXXXXXXX". The word "hame" is a typo — it should be "name" or a proper example such as "email@example.com". This is shown to every single user who visits the login page.

✅ Expected
Placeholder: "name@email.com or 01XXXXXXXXX"
❌ Actual
Placeholder: "hame@email.com or 01XXXXXXXXX" — visible typo
BUG-FUNC-010 Contact Form Success/Failure Feedback Not Confirmed After Submission 🟠 High
Page/contact
SectionContact form

After submitting the "Send a secure message" form, it is not confirmed whether a success toast or confirmation message is reliably displayed. Without clear visual feedback, users may submit the form multiple times thinking it failed, resulting in duplicate support tickets.

✅ Expected
Clear success banner: "✅ Message sent! We'll get back to you within 24h." + form resets
❌ Actual
Confirmation feedback unverified — may be absent or not prominent enough
